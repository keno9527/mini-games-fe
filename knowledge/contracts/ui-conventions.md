# 前端交互与视觉约定

## 适用范围与统一边界

本规范约束新增页面、游戏及已有页面中被修改的 UI 区域。已有差异按“待对齐”记录；共享样式变更需检查所有受影响的消费方。本文定义目标规则，当前落地范围见 [页面与样式架构](../architecture/frontend-presentation.md#现状差异与验证边界)。

全站沿用广场的浅纸色背景与深绿导航。游戏内按钮、面板、工具栏使用统一外观与尺寸，游戏主画面保留独立表现空间。

| 区域       | 统一要求                                                                          | 游戏可定义内容                                                           |
| ---------- | --------------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| 全站外壳   | 导航、玩家入口、保存反馈、普通页面宽度与文字层级                                  | 游戏名称、简介、标签等内容                                               |
| 游戏详情   | 标题、返回首页入口、标题栏右侧操作组、加载/异常状态与游戏容器职责                 | 标题内容、可用动作、主画面适配所需的容器尺寸                             |
| 游戏操作区 | 按钮、工具栏、选项、普通统计/说明面板、选关与结果弹层的配色、字族、尺寸及状态表现 | 可用动作、模式/关卡内容、统计指标和帮助文字                              |
| 游戏主画面 | 保持内容可读、输入可达，与操作区有明确边界                                        | 棋盘、画布、棋子、场景、材质、角色、游戏对象、玩法内动效及画面内信息布局 |

按功能判断边界：计分板、设置、暂停/重开、方向/动作控制键属于操作区；棋盘格、牌面、场景中的交互对象属于主画面。将按钮移进 Canvas 绘制或叠在主画面上，不会自动获得独立控件风格。画面内生命条、瞄准提示等与玩法直接关联的信息可融入主画面，独立统计面板仍使用统一样式。

外部游戏在新标签页打开，统一规范覆盖本站入口及外跳提示；第三方页面内部样式与输入能力需单独确认，参见 `src/components/GameLaunchLink.tsx:22`。

## 视觉与控件基线

### 配色与层级

以下角色沿用当前广场来源，统一用于普通页面和游戏操作区；主画面可另设自己的主题变量。

| 角色                   | 基线                                                                       | 当前依据                                                                                       |
| ---------------------- | -------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| 全站背景、导航与主动作 | 浅纸色 `#f3f0e8`，深绿 `#25483e`；主动作使用浅色文字                       | `src/index.css:9`、`src/index.css:26`、`src/index.css:519`                                     |
| 普通面板与边框         | 面板 `#fcfaf4`、边框 `#ded7c7`；通过边框和留白区分内容                     | `src/index.css:230`、`src/index.css:609`                                                       |
| 正文与辅助说明         | 正文深绿灰、辅助文字降低强调；正文与控件使用系统无衬线字族                 | `src/index.css:9`、`src/index.css:167`、`src/index.css:185`                                    |
| 标题与图标             | 保留广场已有标题字族和字号层级；通用图标沿用 Phosphor，图标需表达操作含义  | `src/index.css:46`、`src/index.css:178`、`src/index.css:272`、`src/components/GameCard.tsx:33` |
| 状态                   | 成功/选中与错误/警告可用语义颜色，同时提供文字或图标；颜色不能成为唯一线索 | 保存错误当前见 `src/index.css:572`、`src/components/SaveStatus.tsx:19`                         |

主按钮承担当前区域的主要动作；次按钮用于辅助和取消；风险操作用明确文案与警示状态区分。同一操作组避免多个同等强调的主按钮。游戏主题不得覆盖这些控件的背景、字号、圆角和间距，也不得把像素字、霓虹或木纹扩展到共用操作区。

### 尺寸参数

新增与改动 UI 采用以下统一参数。当前实现中的默认数值及差异见 [布局与视觉基线](../architecture/frontend-presentation.md#当前布局与视觉基线)。

| 控件   | 统一参数                                               |
| ------ | ------------------------------------------------------ |
| 按钮   | 默认高度 44px、字号 14px、圆角 6px；长文案换行时可增高 |
| 面板   | 圆角 10px；内边距桌面 20px、窄屏 16px                  |
| 工具栏 | 间距 12px，空间不足自动换行                            |

尺寸使用同一套规则；窄屏优先换行、重排或增加高度，保留完整文案和可操作区域。棋盘格、游戏对象和画布内部坐标按玩法比例定义，不套用普通按钮尺寸。

### 标题栏与操作组

游戏详情标题栏左侧放“返回首页”和游戏标题，右侧放开始、重新开始、选择关卡等当前游戏支持的操作。空间足够时，标题与按钮组保持同一行并垂直居中，按钮组靠右对齐。

窄屏空间不足时，操作组在同一标题栏内换到下一行，组内按钮继续按 12px 间距换行；保留按钮尺寸和完整文案。换行依据标题与按钮组的实际可用空间，避免在仍能容纳时提前独占下一行。游戏主画面从标题栏下方开始，不重复放置同一组顶部操作。

### 状态与样式归属

| 状态 / 场景      | 规则                                                                              |
| ---------------- | --------------------------------------------------------------------------------- |
| 默认、悬停、按下 | 控件形状和文字位置稳定；反馈不能只在 hover 时出现；禁用控件不呈现可执行的按压反馈 |
| 选中、当前项     | 外观和 `aria-pressed`、`aria-current` 等实际语义一致；选中与禁用分别表达          |
| 禁用、执行中     | 阻止重复提交；保留标签，必要时说明禁用原因；异步操作显示进行中反馈                |
| 键盘焦点         | 保留清晰、未被裁切的 `focus-visible`；颜色需在所在背景上可辨认                    |
| 主题与作用域     | 共用控件由共用规则维护；主画面变量限定在主画面容器内；专用 CSS 使用游戏命名空间   |

`.gs-*` 是现有复用入口，当前仍接受整游戏主题变量覆盖，并存在独立控件实现。新增或修改时核对目标效果，不能仅凭使用了某个类名判定符合规范。令牌和组件的具体抽取方式由后续实现确定。

## 共用交互语义

### 导航与动作

| 场景             | 统一语义                                                                                                        |
| ---------------- | --------------------------------------------------------------------------------------------------------------- |
| 导航与游戏入口   | 跳转使用链接，执行动作使用按钮；详情页“返回”固定返回首页，窄屏仅显示图标时保留可访问名称                        |
| 开始、暂停、继续 | 开始进入新一局；暂停与继续针对同一局，并保留局内状态；仅在游戏支持时提供对应动作                                |
| 重开与重试       | “重新开始”重置当前局；“重试保存”重发待保存结算，保持原记录身份；重玩关卡和重新连接设备使用对应语义              |
| 选关、模式、设置 | 明确当前值、可选与锁定状态；选择和正式开始若为两步，分别展示当前选择与启动动作                                  |
| 取消、关闭、离开 | 取消或关闭不会隐式提交；会丢弃未保存编辑内容的动作需说明影响并确认；重开/离开是否丢失局内进度依照游戏已声明规则 |

操作文案优先使用明确动词，如“开始挑战”“继续游戏”“重新开始”“返回首页”“重试保存”。主题文案可用于标题、说明和结果叙述；核心动作含义保持可辨认。游戏尚未确定的暂停、重开、离开与进度保留规则应标为“待确认”。

### 加载、结果与异常

| 状态           | 用户应看到的内容                                   | 约束                                                                |
| -------------- | -------------------------------------------------- | ------------------------------------------------------------------- |
| 加载与提交中   | 当前在准备或处理什么；较长操作提供占位或状态提示   | 按需使用 `aria-busy` / `role="status"`；避免重复操作与内容剧烈跳动  |
| 空数据         | 为什么没有内容、适用时可执行的下一步               | 与加载中、请求失败分开；不能用空列表掩盖错误                        |
| 异常与恢复     | 可理解的失败原因、重试或返回入口                   | 需要立即处理的错误使用 `role="alert"`；保留可恢复的上下文           |
| 游戏结果与保存 | 游戏的胜负/完成结果，以及独立的待保存/保存失败反馈 | “通关”不等同于文件已保存；保存状态以 API 成功响应和共用保存机制为准 |

全局保存提示保持在共用外壳内，游戏面板和覆盖层不得遮挡或伪造其状态。当前 `SaveStatus` 在没有 pending 记录时不展示横幅；待保存时提供状态和重试（`src/components/SaveStatus.tsx:5`）。游戏结算和保存机制见 [生命周期事件](./events.md)。

### 弹层、输入与可访问性

| 范围       | 规则与验收要求                                                                                                                               |
| ---------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| 弹层       | 提供标题、明确的关闭或取消；打开时焦点进入弹层，关闭后回到触发点或合理位置；Esc 按取消处理，不能提交风险操作；遮罩点击关闭不得跳过未保存确认 |
| 语义与名称 | 控件使用适当语义；纯图标动作有可访问名称，装饰图标隐藏；错误与选中状态不能只靠颜色、声音或位置表示                                           |
| 键盘       | 普通控件可通过键盘访问；游戏快捷键说明就近展示，不抢占输入框或弹层操作；具体玩法键位由游戏定义                                               |
| 触屏与手柄 | 不以 hover 为必要条件；触屏布局结合输入能力和可用空间；游戏声明实际支持的设备和断连处理，不能因页面变窄就假定有触控能力                      |
| 动效与滚动 | 尊重减少动效偏好，优先关闭装饰性动画；玩法关键动画由游戏说明；限制触摸/滚动的规则仅作用于需要接管输入的游戏区域                              |

上述条目是验收要求；全页面焦点、对比度、设备覆盖尚需按 [UI 走查手册](../runbooks/ui-review.md) 验证。当前已存在 `dialog` 和 `window.confirm` 两种确认交互，浏览器原生确认框的外观尚不符合统一控件目标。

## 游戏可以定义的细节

游戏可在主画面内设计独立主题和布局，同时为玩法与共用交互的交界提供可核对的定义。简单游戏可以在就近说明、设计材料或代码与测试中表达，不强制每个游戏新增文档。

| 需要定义的内容 | 说明要点                                                                                 |
| -------------- | ---------------------------------------------------------------------------------------- |
| 主画面范围     | 棋盘/画布边界、主题、画面内信息、比例和最小可用布局；与共用操作区的分界                  |
| 玩法与反馈     | 目标、胜负/完成判定、关卡与难度、得分和即时反馈；规则与帮助文字一致                      |
| 操作与设备     | 键盘、鼠标、触屏或手柄支持范围；关键动作、长按/拖动、设备断连与焦点变化处理              |
| 状态与保留     | 开始、暂停（如支持）、重开、选关、退出、切换玩家的状态变化；哪些进度保留、何时结算和保存 |
| 布局边界       | 窄屏、低高度横屏、长文本、画面缩放与指针映射；必要的特殊布局与原因                       |

例如，象棋可以使用木质棋盘与棋子，坦克可以使用像素战场；两者的“重新开始”、选关、帮助与结果操作仍使用同一套控件。棋盘格或场景对象的形状尺寸随玩法确定，主画面外的按钮与面板不另设游戏主题。

## 落地与例外

新增 UI 和改动区域按本文验收；受影响的既有差异在评审中列明。只改业务逻辑且不影响 UI 的变更，不触发全游戏视觉重做。涉及共享 CSS 时需检查消费范围和页面往返，防止一个游戏的样式影响另一款游戏。

现有已确认差异集中记录于 [页面与样式架构](../architecture/frontend-presentation.md#现状差异与验证边界)，不将待对齐项视为默认例外。确需突破共用控件规范时，先给出场景、原因、影响范围和替代方案，确认后记录为有范围的例外。尚未确定的数值或行为保留“待确认”，未执行的验证保留“待验证”。
