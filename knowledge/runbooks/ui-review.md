# UI 走查与验收

本手册用于页面与游戏 UI 的开发自检和评审。[交互与视觉约定](../contracts/ui-conventions.md) 定义目标规则，[页面与样式架构](../architecture/frontend-presentation.md) 提供源码定位。验收需分别记录本次改动是否符合规范、受影响的现有差异和未验证环境。

## 确定范围与准备环境

| 准备项       | 记录内容                                                       |
| ------------ | -------------------------------------------------------------- |
| 变化与边界   | 页面/游戏、涉及控件、主画面自定义内容、共享 CSS 的消费方       |
| 对照依据     | 规范条目、设计图或前后截图；若有例外，记录原因、影响和确认结论 |
| 数据与状态   | 测试玩家、空数据/历史记录、待保存状态、关卡或设备条件          |
| 浏览器与输入 | 浏览器、视口、缩放、鼠标/键盘/触屏/手柄，以及是否使用真实设备  |

在本机通过 `npm run dev` 访问 Vite 输出的地址。玩家操作与游戏结算可能写入 `data/players/*.json`，使用隔离的临时 checkout 与测试玩家；数据隔离说明见 [排障手册](./debugging.md#备份与恢复边界)。页面缩略图、Node 测试和浏览器设备模拟各自只能证明对应范围，触屏和手柄适配需要记录实际验证方式。

## 场景矩阵

### 页面与关键状态

| 场景               | 检查重点                                                                                 | 现状线索                                                        |
| ------------------ | ---------------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| 玩家入口与个人战绩 | 恢复中、无玩家、长玩家名、创建/切换/归档、加载失败；标题和表单可读，操作有反馈           | `PlayerGate`、`UserSelector`、`Profile`                         |
| 广场列表与排行     | 卡片对齐、标签换行、加载占位、配置失败、排行空数据与请求失败；内置/外部入口语义          | `Home`、`GameCard`、`GameLaunchLink`                            |
| 游戏详情与操作区   | 返回首页、加载中、无效 ID、主次操作、禁用/选中、关卡切换、结算反馈；切换游戏后样式不串用 | `GameDetail` 与实际游戏组件                                     |
| 保存与恢复         | 保存中、失败、待保存数量、重试后恢复；胜负结果与文件保存状态分别表达                     | `SaveStatus`，保存契约见 [生命周期事件](../contracts/events.md) |
| 弹层与设备         | 选关、确认、编辑器未保存退出；焦点进出、Esc、取消；设备不支持/断连与替代操作说明         | 象棋选关、游戏编辑器、`GamepadTest`                             |

对不存在的功能标记“不适用”并说明原因，例如没有暂停机制的回合制游戏无需凭空增加暂停按钮。请求失败与空数据分别构造；首页排行当前忽略错误，应记为已有待对齐项，不能据此通过错误反馈验收。

### 布局与输入

| 维度           | 最小检查方式                                                                        | 通过条件                                                                   |
| -------------- | ----------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| 宽屏与窄屏     | 选一个桌面宽度、一个窄屏宽度，并在改动涉及的断点两侧检查；可用 1440px、390px 作样例 | 导航、保存提示和操作区完整可用；按钮尺寸遵循规范；无非预期横向滚动         |
| 容器与低高度   | 改变侧栏/容器宽度，检查低高度横屏；棋盘和画布在缩放后再次操作                       | 容器规则实际触发，内容不被覆盖，指针坐标与画面一致                         |
| 长内容与缩放   | 长标题、玩家名、错误文案；浏览器放大至 200% 作检查样例                              | 必要信息与动作可达；面板可增高、工具栏可换行                               |
| 键盘与焦点     | Tab/Shift+Tab 遍历，激活按钮/链接，打开和关闭弹层                                   | 焦点可见、顺序合理；弹层关闭后回到触发点或合理落点；游戏快捷键不抢表单输入 |
| 触屏与动效偏好 | 检查粗指针条件、触控命中、滚动边界与减少动效偏好；涉及手柄时补实际设备              | 操作不依赖 hover；游戏按需处理触控，页面仍可正常滚动；装饰性动效可减少     |

样例视口用于发现问题，不能代替项目支持范围的定义；各游戏根据棋盘比例、输入方式补充边界。共享样式变更至少检查普通页面、一款采用 `.gs-*` 的游戏和受影响的独立样式游戏；单游戏变更检查它与相邻路由之间的往返。

## 视觉与交互检查顺序

1. **先看结构**：全站导航、游戏标题与返回入口清晰；空间足够时，标题居左、操作组同一行靠右且垂直居中；窄屏放不下时才在标题栏内换行，主画面位于其下方。检查 736px 等中间宽度，避免提前折行。
2. **再看一致性**：按钮、面板、工具栏按统一外观与尺寸；主题差异限定在主画面；核对计算样式和游戏主题变量是否越界。
3. **再走状态**：正常、进行中、禁用、成功、空数据、失败和重试；同一操作保持同一含义，未保存状态明确。
4. **最后看边界**：窄屏、长文字、输入设备、焦点、弹层、减少动效；回到首页与另一款游戏检查共享 CSS 泄漏。

截图对比应固定视口、玩家和关卡状态，并等待字体、素材加载稳定。首页会在每次进入时打乱未排行游戏的顺序（`src/pages/Home.tsx:34`），按游戏 ID 对照卡片，避免把顺序变化当作视觉缺陷。

## 结果记录与检查命令

| 结果       | 记录要求                                                               |
| ---------- | ---------------------------------------------------------------------- |
| 通过       | 具体页面、状态、环境与截图/操作证据                                    |
| 待对齐     | 现有差异、规范条目、源码位置及用户影响；涉及本次修改的控件需按规范验收 |
| 未通过     | 可复现步骤、实际/预期、影响范围与修正后验证结果                        |
| 待验证     | 缺失的浏览器、设备或状态条件；保留未验证结论                           |
| 已确认例外 | 确认结论、必要性及适用范围；例外不自动扩展到其他游戏                   |

仅修改知识库时检查格式、链接、源码引用和 diff：

```bash
npx prettier --check 'knowledge/**/*.md'
git diff --check
git diff --name-only
```

涉及组件或样式改动时，按 [测试手册](./testing.md) 执行相关类型、lint、构建或行为测试，并补充上述真实浏览器走查。报告中区分“文档检查通过”“自动化检查通过”和“浏览器走查通过”；只有实际执行的项目才能标记通过。
